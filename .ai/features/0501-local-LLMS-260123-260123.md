# Feature: local-llms
**ID**: 0501
**Created**: 2026-01-23
**Last Updated**: 2026-01-23
**Status**: DRAFT

## 1. Objective
Implement dynamic support for a **Local AI Stack** using the `USE_LOCAL_EMBEDDING` configuration as the primary trigger. This stack must support two distinct classes of models to fulfill four key operational roles:

1.  **Tokenization/Embedding**: Converting text to vectors for storage.
2.  **Querying Data Sources**: Direct reasoning over raw files (Direct Parsing).
3.  **Querying Qdrant**: Retrieval Augmented Generation (RAG) over stored vectors.
4.  **Chatbot**: General purpose conversational interface.

## 2. Analysis & Requirements

### 2.1 Model Roles
The system uses a **Single Local Model** (e.g., `dolphin-x1-8b`) to handle all local AI, including Embedding and Chat functions if capable, or primarily Chat.

*   **Config**: `LOCAL_MODEL_NAME`

### 2.2 Dynamic Orchestration
- [ ] **Master Switch**: `USE_LOCAL_EMBEDDING` (Env Var).
    -   **True**: The Docker stack **MUST** starts the `llm-dl` (Ollama) container.
    -   **False**: The `llm-dl` container is excluded to save resources.
    -   **Strategy**: Docker Compose Profiles (`profiles: ["local-llm"]`).

### 2.3 Hardware Optimization
- [ ] **GPU Detection (Rust)**:
    -   Backend must detect NVIDIA GPU availability (`nvidia-smi` check).
    -   **Optimization**: If valid GPU found, pass `--gpus all` to Docker (via Compose Override or Configuration).
    -   **CPU Fallback**: If no GPU, warn user of high latency for Generative tasks.

### 2.4 User Interface (Settings -> LLM)
- [ ] **Toggle**: "Enable Local AI / Embeddings".
- [ ] **Hardware Status**: Indicator for "GPU Active" vs "CPU Mode".
- [ ] **Model Selection**:
    -   **Model**: Dropdown/Input (e.g., `dolphin-x1-8b`).
    -   **Pull Action**: Button to "Download/Pull" selected models if missing.

## 3. Architecture & Design

### 3.1 Docker Composition
**`docker-compose.dev.yml`**:
```yaml
services:
  llm-dl:
    image: ollama/ollama:latest
    container_name: iadata_llm_${DEPLOY_SUFFIX}
    profiles: ["local-llm"]
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
    volumes:
      - ollama_data:/root/.ollama
    ports:
      - "11434:11434"
    networks:
      - iadata_net
```
*Note: GPU reservation in Compose requires the NVIDIA Container Toolkit on the host.*

### 3.2 Configuration Strategy
**Env Variables**:
-   `USE_LOCAL_EMBEDDING=true/false` (Master Trigger)
-   `LOCAL_MODEL_NAME=dolphin-x1-8b`

### 3.3 Rust Backend Logic
-   **`detect_gpu()`**: Execute `nvidia-smi`. Return success/fail.
-   **`start_docker()`**:
    -   Check `USE_LOCAL_EMBEDDING`.
    -   If true, set `COMPOSE_PROFILES=local-llm`.
    -   Run `docker compose up -d`.

### Phase 2: Hardware Awareness

- [ ] **UI**: Show hardware status badge.

### Phase 3: Model Configuration
- [ ] **UI**: Create "LLM" Settings Tab.
- [ ] **UI**: Add Model Selectors (Embedding vs Chat).
- [ ] **Backend**: Implement `pull_local_model(model_name)` (proxies `docker exec llm-dl ollama pull ...`).

## 5. Risks
-   **Hardware Prereqs**: GPU support requires NVIDIA drivers + Container Toolkit installed on Host. If missing, Docker may fail to start if `deploy.resources` is strict. Needs "Best Effort" configuration or distinct GPU/CPU compose overrides.
-   **Resource Consumption**: Running two models (even if swapped) is memory intensive.
