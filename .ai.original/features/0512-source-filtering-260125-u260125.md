# Feature: Source Filtering (RAG Isolation)

## Goal
Enable the Chat/RAG system to limit its context search to specific Data Sources. This allows creating "Environments" where the LLM only knows about a subset of documents (e.g., "Finance Only", "Project X Only").

## User Review Required
> [!IMPORTANT]
> **API Change**: The `/chat/` endpoint signature will change to accept an optional `filter` object containing `source_ids`. Client applications (Frontend) must be updated to utilize this new field.

## Proposed Changes

### Backend (`tools-iadata`)

#### [MODIFY] [vector_service.py](file:///mnt/work/Projects/tauri/datalake/tools-iadata/back-dl/app/services/vector_service.py)
- Update `search()` method to accept `filters: dict = None`.
- Implement Qdrant `Filter` construction using `qdrant_client.models`.
- Support filtering by `source_id` (MatchAny logic).

#### [MODIFY] [chat.py](file:///mnt/work/Projects/tauri/datalake/tools-iadata/back-dl/app/routers/chat.py)
- Update `ChatRequest` Pydantic model:
    ```python
    class ChatRequest(BaseModel):
        # ...
        filter: Optional[Dict[str, Any]] = None # e.g. {"source_ids": ["uuid-1", "uuid-2"]}
    ```
- Extract `source_ids` from request filter.
- Pass filter payload to `vector_service.search`.

## Verification Plan

### Automated Tests
1.  **Test Filtering**:
    - Ingest Document A (Source 1) and Document B (Source 2).
    - Query with `filter={'source_ids': ['Source 1']}`.
    - Assert that only Document A is returned in `sources`.
2.  **Test No Filter**:
    - Query without filter.
    - Assert that both A and B are potential candidates.

### Manual Verification
1.  Use Swagger UI (`/docs`) to send a chat request with a specific `source_id` (obtained from DB).
2.  Verify the `sources` list in the response only contains that ID.
