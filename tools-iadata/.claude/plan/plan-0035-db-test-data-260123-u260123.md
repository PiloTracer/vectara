# Plan 0035: Database Test Data Population

## Overview
To provide a ready-to-use "Data Lake" experience out of the box, we will populate the database with a meaningful set of Environments, Sources, Agents, and MCPs. This data will be "technically realistic" to demonstrate the system's capabilities.

We will also implement a **Script Runner** in `db.py` to execute SQL files from `back-dl/app/sql/` sequentially on startup.

## 2. Implementation: SQL Script Runner

We will modify `back-dl/app/db.py` to:
1.  Scan `app/sql/*.sql` sorted by filename.
2.  Execute each script inside the `init_db` transaction.
3.  Ensure the scripts are idempotent (using `ON CONFLICT DO NOTHING`).

## 3. The `populate-test.sql` Script

This script will use UUIDs generated deterministically (or hardcoded for the demo) to ensure consistent re-runs, via `INSERT ... ON CONFLICT DO NOTHING`.

```sql
-- Example Idempotent Insert
INSERT INTO environments (id, name, owner_id)
VALUES ('...', 'Operations', '...')
ON CONFLICT (id) DO NOTHING;
```
